## Architecture implications

**Sources state:** Apollo's API is on every plan including Free; it charges enrichment and organization search, not people search, and bills standard enrichment only when data is found. Its terms bar multiple self-serve accounts. Clay webhooks and HTTP API start at Growth ($495/mo); Clay API is Enterprise-only; no-result enrichments are free. Meta's API excludes US/CA commercial ads, and scraping its UI needs written permission. Quebec open data is reported non-commercial.

**Inference (mine):**
- Consumption models need per-endpoint units (0, 1 per page, 1-9 per person), `charged_on` = success | attempt | conditional, and daily, monthly or annual windows.
- Add `interface` = api | mcp | human: Clay Free and Meta's UI are not machine-callable.
- A `pooling: forbidden` flag should stop the router adding a second Apollo or Clay account.
- Facts need a `license` attribute so non-commercial data cannot reach campaigns.
- Ads lookup is a human evidence task feeding the approval queue.
- Free tiers cover tens of leads/day only if rationed (Reoon 20/day, Apollo about 75 credits/month).
