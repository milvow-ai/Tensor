## Areas checked with no findings

- **Atomicity of the quota SQL** (`farm_reserve` / `farm_commit` / `farm_release`): single-row lock plus guarded update, idempotent commit/release, expiry uses `skip locked`; the concurrency acceptance test passes. The only gaps are Q0-13/14.
- **Every success, failure, timeout and cancel path settles its reservations** in `_try_connection` (`shield`ed settle, `except BaseException`), and a pinned job's cancellation propagates to the executor (no `shield` on the pinned path), so `ai_cancel` kills the CLI tree and settles quota. Only the small window of Q0-21 is open.
- **`pin`** skips cache and single-flight and keeps eligibility (`skip_reason`, circuit probe, budget, reserve); session-pinned calls fail without falling back to other accounts.
- **Fallback order** follows route position per pool, then strategy order per pool; busy accounts move to the back by design (logged as `saturated`).
- **Single-flight in one process**: joiners get the leader's task result (`.free()`), the leader runs as its own task and settles even if its caller goes away.
- **Guarded job transitions** (`mark_running`, `requeue`, `finish`, `request_cancel` all carry `where state = …`/owner), the unique index that allows one queued/running job per conversation, `retry_other_account` limited to first-turn `answer` jobs and never repeating an account (`tried`), failure kinds mapped from router errors without scanning the answer text.
- **Pass-through MCP relay**: a tool's `isError` and JSON-RPC rejections are relayed as results; only the path fails over; error strings go through `redact`; token store path traversal is guarded; the single-client-auth fix for Basic auth is in place.
- **Period arithmetic**: SQL `farm_period_start` and Python `periods.py` agree (including month anchor clamping); the `v_spend_month`, `v_pool_overview` (aggregation per connection before pool sums), `v_spend_daily` and `v_cost_per_result` spend sums do not double count rows; month and day boundaries are UTC in all views and in Python.
- **Command validation**: unknown kinds and invalid payloads are rejected before any write (strict Pydantic payloads); successful commands write an `audit_events` row (but see Q0-10, Q0-17).
- **Not audited (outside the brief's list):** `farm/executors/cli_agent/*` classification (D1), gateway tools, Console TypeScript.

## Spend double counting (note, not a finding)

`get_month_to_date_spend` and the Console add `usage_events.cost_usd` and `billing_events.amount_usd` per scope. For a prepaid
credit pack that has both a `credit_purchase` billing event and a per-unit `unit_cost_usd`, the same money is counted twice
(`router.py` says "configure the price in one of the two places"). Nothing enforces that rule; a registry validation would.
