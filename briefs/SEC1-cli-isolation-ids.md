# Brief SEC1 — security fixes from the M1 gate: AI-CLI isolation (env, argv, edit mode) and safe ids

Rules: follow `briefs/CONTEXT.md` §6 and §0. Touch only the files under "Owns". Never git add/commit/push. Never read `.env` or any real credential/token file. No live provider calls.

## Why (proven by the M1 security review, 2026-10-04)
1. **Critical — secrets leak into child CLIs.** `farm/executors/cli_agent/base.py` (`run_cli_process`) builds the child environment with `os.environ.copy()`. A fake `claude` that dumped its env received `FARM_DB_URL` (with password), `SUPABASE_SERVICE_ROLE_KEY`, a provider key and `BIFROST_FARM_VK`. That violates the core rule "delegated AIs never see provider keys or DB credentials" (CLAUDE.md, HANDOFF §4.7, docs/HERMES-INTEGRATION §14). Those values also never pass through `resolve_auth`, so `redact()` cannot mask them if a sub-agent echoes one.
2. **Edit mode is unconfined.** `claude.py`/`codex.py`/`agy.py` use permission-skip flags (`--permission-mode acceptEdits`, `--sandbox workspace-write`, agy's skip-permissions flag) in `mode=edit`, and `cwd` is any caller-supplied path that gets `mkdir(parents=True)`.
3. **Argv injection / length on Windows (lead's addition).** npm-installed CLIs (e.g. `codex.cmd`) are batch shims run by `cmd.exe`; argv quoting cannot neutralise cmd metacharacters (`&`, `|`, `%VAR%`, `^`) in batch arguments (the CVE-2024-24576 class), so a task text containing them could run commands. The Windows command line is also capped at ~32 K chars, so long delegated tasks fail.
4. **Major — path traversal via connection ids.** `farm/executors/mcp/client.py:get_token_store_dir` falls back to `data_dir/"tokens"/connection.id`; ids are validated only by the Console's zod, not by the Farm (`commands.py` payloads, registry models, DB column), so `..\..\x` creates a directory outside `tokens/`.

## Requirements
1. **Child env allow-list** in `base.py`: `build_child_env(extra)` returns only OS essentials (`PATH, PATHEXT, SYSTEMROOT, WINDIR, COMSPEC, TEMP, TMP, USERPROFILE, HOMEDRIVE, HOMEPATH, APPDATA, LOCALAPPDATA, PROGRAMDATA, PROGRAMFILES, PROGRAMFILES(X86), NUMBER_OF_PROCESSORS, PROCESSOR_ARCHITECTURE, OS, HOME, LANG, LC_ALL, TERM`) plus the driver's own vars (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `TERMINAL_CWD`, …) and `NO_COLOR=1`. Anything whose name or value looks secret (`*KEY*`, `*TOKEN*`, `*SECRET*`, `*PASSWORD*`, `*_VK`, `*DB_URL*`, `DATABASE_URL`, `postgres://…:…@`) is never passed, even if a driver asks. Test: parent env holds `FARM_DB_URL` with a password, `SUPABASE_SERVICE_ROLE_KEY`, `APOLLO_API_KEY`, `BIFROST_FARM_VK`, `OPENROUTER_API_KEY`; each of the four drivers' fake CLIs dumps its env → none present (sentinel assertions), the driver's config var present.
2. **Redaction of environment secrets:** `register_env_secrets()` registers every secret-looking env value (and the password part of any DB URL) with `register_secret`; called at the end of `load_env()`. Test: after load, `redact()` masks each of them inside arbitrary text.
3. **No cmd.exe, no argv overflow:** deliver the task text through **stdin** for every CLI that supports it (verify with each CLI's `--help` and docs; claude `-p` reads the prompt from stdin when omitted; check codex `exec -`, agy `--input-format`, hermes) — otherwise through argv only to a real `.exe`/binary. If the resolved executable is a `.cmd`/`.bat` shim, resolve it to its target (e.g. npm shim → `node <script>`) and run that directly, or refuse with BAD_REQUEST — never run a batch file with untrusted text. Tests (fakes): a task containing `& echo injected > marker.txt` (benign marker in a temp dir) arrives byte-exact and the marker is never created; a 60 000-char task arrives intact (or returns a clear BAD_REQUEST if a CLI truly cannot take stdin).
4. **Edit-mode confinement:** `mode=edit` only when the connection's `meta.allow_edit` is true (owner opt-in) AND `cwd` resolves (after `resolve()`, symlinks followed) inside an allowed root (`meta.edit_roots`, default `FARM_DATA_DIR/workspaces`); never `mkdir` a caller path — it must already exist inside the root; permission-skip flags only in edit mode; `answer` mode uses each CLI's read-only/no-tools setting. Violations → `BAD_REQUEST` with a clear message (no execution). Tests for each driver.
5. **Safe ids, enforced by the Farm:** one shared `SLUG` pattern (`^[a-z0-9][a-z0-9_-]{0,62}$`) applied to provider ids, connection ids and every `*_id`/`id` field in command payloads and registry models; DB CHECK constraints (migration 0004); `get_token_store_dir` asserts the resolved path stays inside `<data_dir>/tokens` (raise otherwise). Tests: `..\..\x`, `a/b`, uppercase, empty → rejected at the payload, the registry and the DB; the executor refuses a crafted id even if it bypasses the payload layer.
